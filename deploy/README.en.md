# FarHelm minimal deployment

[简体中文](README.md) · [English](README.en.md)

Bundles target Ubuntu 24.04 x86_64, or a compatible systemd distribution with glibc 2.39+. The public host needs Caddy or an equivalent HTTPS reverse proxy. The training host needs Python 3.12 and opens no inbound port.

## 1. Public server

Upload and extract `farhelm-hub-0.1.0-linux-x86_64.tar.gz`:

```bash
tar -xzf farhelm-hub-0.1.0-linux-x86_64.tar.gz
cd farhelm-hub-0.1.0-linux-x86_64
sudo ./install.sh
```

The installer generates an admin password and an Agent token, displays them once, and stores them in `/etc/farhelm/hub.env`. Replace the hostname in `Caddyfile.example`, merge the site block into `/etc/caddy/Caddyfile`, then run:

```bash
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
curl https://your-domain.example/api/v1/health
```

Expose only ports 80/443 in the firewall or cloud security group, never port 8787. Open the HTTPS URL and sign in with the generated admin credentials.

## 2. Training server

Use the Agent token generated by the Hub installer:

```bash
tar -xzf farhelm-agent-0.1.0-linux-x86_64.tar.gz
cd farhelm-agent-0.1.0-linux-x86_64
sudo FARHELM_RUN_USER="$USER" \
  FARHELM_HUB_URL="https://your-domain.example" \
  FARHELM_AGENT_TOKEN="agent-token-from-hub" \
  FARHELM_AGENT_ID="gpu-a" \
  ./install.sh
```

Check the connection:

```bash
systemctl status farhelm-agent
journalctl -u farhelm-agent -n 50 --no-pager
```

Within one heartbeat interval, the Console Servers page shows the real hostname, Agent ID, version, last heartbeat, and online state.

## Security notes

- Never expose Hub directly. The application rejects a non-loopback bind.
- Never paste `/etc/farhelm/*.env` into chat, Git, or public logs.
- Restart the appropriate service after changing configuration.
- This version reports presence only. It cannot control training and does not connect to real Codex.
